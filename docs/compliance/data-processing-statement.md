# 人脸信息数据处理说明（致业主）

- 出具对象：业主（学校）管理层与个人信息保护负责人
- 出具方：系统开发/运维方
- 版本：v1.0（出具日期：2026-11-23，随 CR-028 交付）
- 配套文本：《人脸信息采集与使用告知（同意书 v2）》（`docs/compliance/face-consent-notice-v2.md`，面向学生）
- 用途：帮助业主履行《个人信息保护法》（PIPL）项下的**告知义务**与**处理者责任**，作为合规底稿；**本文件不替代法律意见书**，正式对外承诺以业主法务审阅后的版本为准

---

## 一、角色界定（谁对什么负责）

| 角色 | 主体 | 职责 |
|---|---|---|
| **个人信息处理者** | 学校（业主） | 决定处理目的与方式；对学生履行告知与取得单独同意义务；承担 PIPL 主体责任；处理学生行使权利的请求（删除、撤回、查询、投诉） |
| **受托处理者 / 技术支持** | 系统开发与运维方 | 按委托范围实施技术处理；不得超范围使用数据；落实安全措施；协助处理数据主体请求与安全事件 |

**结论**：学生对外的《告知同意书》以学校名义出具（见配套文本，占位符由学校填写后生效）；本系统在产品内实现"告知 → 单独同意 → 处理 → 可撤回可删除"的完整闭环，并为学校留存同意凭证。

## 二、处理活动清单（数据映射）

| 数据项 | 处理目的 | 合法基础 | 存储位置 | 保留期限 | 删除方式 |
|---|---|---|---|---|---|
| 相机画面（人脸图像） | 采集质检与活体检测 | 单独同意 | **内存，不落盘** | 不保留 | 无需（从不持久化） |
| 采集样本中转（含向量缓存） | 采集链路暂存 | 单独同意 | Redis（DB0） | TTL 15 分钟（`FA_ENROLL_SAMPLE_TTL`） | 自动过期 |
| 活体挑战状态 | 动作/被动活体门禁 | 单独同意 | Redis | 会话级 TTL（约 1 分钟） | 自动过期 |
| 人脸特征向量（512 维，加密） | 签到 1:1 / 1:N 比对 | 单独同意 | MySQL `face_vector`（AES-256-GCM 字段级加密） | 至撤回/删除/学籍异动 | 学生自助删除 / 管理员删除 / 归档与硬删级联 |
| 人脸档案状态 | 采集-审核状态机 | 单独同意 | MySQL `face_profile` | 同上 | 同上 |
| 同意事件（版本+时间） | 举证"取得单独同意" | 履行法定义务所必需 | MySQL `face_consent_record`（事件流只增不改）+ `account.face_consent_*` 当前态 | 随账号生命周期 | 撤回写入 WITHDRAW 事件并清当前态 |
| 考勤/签到记录 | 教学管理 | 履行法定或约定职责所必需（非人脸信息） | MySQL `attendance` 等 | 按学校学籍制度，系统不自动清理 | 学校依制度处理 |
| 审计日志 | 安全与问责 | 履行法定义务所必需 | MySQL `audit_log` | 365 天，到期自动清理（`LogRetentionJob`） | 自动 |
| AI 助手问答/动作留痕 | Agent 审计 | 履行法定义务所必需 | `agent_query_log` / `agent_action_log` | 180 天，到期自动清理 | 自动 |
| 数据库备份 | 容灾 | 与库内数据同 | 备份产物（AES-256 整体加密） | 滚动 7 天（`BACKUP_KEEP_DAYS`） | 自动过期删除 |
| 容器运行日志 | 运维 | 运维必需 | Docker json-file | 10MB × 3 滚动 | 自动轮转 |

## 三、告知与单独同意的实现（PIPL §29 落地）

1. **文本**：《人脸信息采集与使用告知（v2）》全文，含处理者身份、目的、清单、保留期限、删除方式、安全措施、不同意后果、投诉渠道全部要素；占位符（学校名称、负责人、联系方式）由业主填写。
2. **时机**：同意弹窗在**打开摄像头之前**强制展示；点遮罩不关闭，必须显式二选一（不同意 → 立即退出，不采集、不落库、不开摄像头）。
3. **非捆绑**：同意仅针对人脸采集事项本身，不与用户协议捆绑；勾选框（v1 形态）已移除。
4. **凭证**：同意事件（账号、学生、版本、时间）写入 `face_consent_record` 事件流，只增不改；`account.face_consent_at/version` 供展示；同一版本重复同意不刷新首次时间。
5. **升版**：告知文本实质变更 → 版本号升版 → 学生须重新同意（旧同意不自动顺延）；前端常量与服务端常量双侧同步。
6. **服务端强校验**：采集提交（enroll）时校验 consentVersion 等于当前生效版本且存在对应 ACCEPT 事件，否则拒绝落库——同意不依赖前端状态。

## 四、个人信息主体权利的实现

| 权利 | 实现 |
|---|---|
| 知情权 | 同意书 v2 全文 + 采集页常驻摘要 |
| 单独同意/拒绝权 | 前置弹窗显式二选一；拒绝即退出且零落库 |
| 撤回同意 | 「删除我的人脸数据并撤回同意」按钮（采集页），一键撤回并写 WITHDRAW 事件 |
| 删除权 | 同一按钮物理删除向量与档案（无需审批）；教师/管理员代删与学生硬删/归档级联（CR-028 起**归档学生人脸数据同步物理清除**） |
| 查询/复制 | 本人档案状态与同意版本、时间经 `/mobile/face/status` 可查；导出能力见 CR-020（Agent 导出，仅考勤字段，不含人脸数据） |
| 投诉 | 告知书第九节载明学校联系渠道与答复时限 |

**撤回/删除的语义边界（需业主知悉并向学生说明）**：删除对象为人脸相关数据（向量、档案、同意态）；既往签到产生的考勤记录是教学管理凭证、不构成人脸信息处理，**不随人脸删除而清除**。该边界已写入同意书 v2 第四节与第五节。

## 五、安全措施清单

| 措施 | 说明 |
|---|---|
| 字段级加密 | 向量 AES-256-GCM 应用层加密（CR-012），密钥经环境注入、不入库不入 git；密文含版本字节，支持渐进重加密 |
| 备份加密 | dump 完整性校验后 `openssl AES-256-CBC-PBKDF2` 整体加密，明文即删；备份密钥与库密钥分离 |
| 原图不落盘 | 采集/签到画面仅在内存处理，架构上不存在照片泄露面 |
| 访问控制 | RBAC（管理员/教师/学生）+ 数据范围授权（教师仅见授权班级/课程）；向量接口仅限服务间内部调用；学生仅能操作本人数据（服务端按登录身份取 studentId，不接受代提交） |
| 审计 | 采集、同意、审核、删除、管理员删除/归档全部落审计日志 |
| 传输安全 | 线上部署全程 HTTPS |
| 输入面收敛 | 微信内置浏览器硬性禁止采集（WeChatGuard）；人脸服务错误码语义化（如多脸 FA-4002、重复档案 FA-4008） |
| 保留期自动化 | 日志清理定时任务（`LogRetentionJob`）、Redis TTL、备份滚动、容器日志轮转 |

## 六、已知残余风险与建议（如实披露）

1. **占位符未填**：同意书中的学校名称/负责人/联系方式为占位符，业主填写并确认前，告知文本不具备对外生效条件；
2. **存量同意迁移**：v1（勾选框）时期已入库的学生，其同意记录为旧口径（仅 `account.face_consent_*`，无事件行）。此类学生重新采集时会被要求按 v2 重新同意；已有档案不受影响；
3. **活体阈值未完成真机标定**：被动活体（第四道门禁）默认关闭，开启前须用真机素材重标定（`scripts/calibrate_passive.py`）——合规交付与效果验收是两件事，本说明只覆盖合规侧；
4. **专用错误码**：`FA-4010 FACE_CONSENT_REQUIRED`（400，未取得人脸采集单独同意）已随 CR-028 落地（四处契约同步）；仅"暂无人脸数据可删除"沿用 `FA-2001`（404）；
5. **告知文本的对外分发**：同意书 v2 目前仅随产品内弹窗展示；建议业主同步在教学管理渠道公示一份 PDF/纸质文本（Word 版已随本次交付生成）；
6. **项目文档 §13 口径**：项目文档 §13.4 已按 CR-028 修订（单独同意 v2 / 自助删除 / 保留期限 / 原图不落盘对齐 CR-012）；
7. **测试环境说明**：测试/演示环境使用公开学术数据集（CASIA）构造数据；生产环境人脸数据不用于任何模型训练。
