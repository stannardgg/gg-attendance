## 三处刻意的设计偏离（需评审确认）

1. **`fa-auth` 依赖 `fa-org`**
   学生激活要按「学号 + 姓名 + 班级码」查 `student`，这属于组织域数据。
   让 auth 依赖 org 的 Service/领域对象，比在 auth 里复制一份查询（两份 SQL 各自漂移）好。
   §9.1 的依赖方向写的是 `bootstrap → {auth, org,…} → infra → common`，此处等于同层依赖。
   替代方案是抽一个 `StudentActivationPort` 到 common，但对一个方法来说过度设计。

2. **参数校验失败复用 `FA-2001`**
   契约 2xxx 号段没有「通用校验失败」码，而 §6.4 自己就用 `FA-2001` 表示
   「不过 `POST /admin/sessions` 缺 classId 或 courseId」。校验失败属同一类，复用更一致。
   **建议下一个大版本补一个 `FA-2007 参数校验失败`**，已在 CR 待办里记一笔。

3. **`NameLookup` 用 `JdbcTemplate` 直读 `teacher.name`**
   列表页要展示「负责教师姓名」，但 org 不能依赖 auth（auth 已依赖 org，会成环）。
   只读一个展示字段、不参与业务判断。B4 引入统一查询层时替换。

## 给下一个包的话

1. **`account.admin_singleton` 与 `appeal.pending_attendance_id` 是生成列**，实体里不要加这两个字段，
   否则 insert 会报 "The value specified for generated column is not allowed"。
2. **`@DataScope` 必须加在 Service 方法上**，不是 Controller。切面在 fa-org，
   靠 `ScopeContext` 传递；忘了加会抛 `IllegalStateException`，不会静默放行。
3. **空权限集合等于什么都看不到**。写 `if (allowed != null && !allowed.isEmpty())` 时
   少写后半个条件就是越权——`OrgIT` 里有专门用例盯着。
4. **`fail-on-unknown-properties=true` 是全局的**。B4 新增 DTO 时，前端多传一个字段会直接 400，
   这是有意的（场景 16 依赖它），但联调时容易被误认为「接口坏了」。
5. 集成测试要 POST 带 body 并断言 401 时，**必须用 Apache HttpClient**，
   JDK 的 HttpURLConnection 会抛 `HttpRetryException`。
