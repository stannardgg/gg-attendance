> 与文档**不一致**的地方集中在两处，均以「加法」形式落地，未改动任何锁定字段：
> 1. 补了 4 个索引（`course.semester`、`checkin_session.teacher_id`、
>    `attendance(session_id,status)`、`face_vector.created_at`）。理由：锁定 DDL 只给了主查询路径的索引，
>    而列表页/定时任务/增量刷新各有一条独立查询。索引不影响任何字段语义。
> 2. `account` 与 `appeal` 各加了一个**生成列**（`admin_singleton`、`pending_attendance_id`）。
>    这两个列是为了把 §9.3「单管理员唯一索引」「FA-5001 唯一 PENDING」落成数据库约束，
>    文档只说了"用生成列实现"，没给列名，此处补全。业务代码不得读写这两列。

### flyway migrate 的真实输出（CI run 44419027606）

本机跑不了（原因见下），所以把这条 Gate 的**执行位置挪到了 CI**。GitHub runner 没有本机那些限制，
拿到的是真实迁移日志，而不是"结构看起来对"：

```
Flyway Community Edition 9.22.3 by Redgate
Migrating schema `face_flyway` to version "1 - schema"
Successfully applied 1 migration to schema `face_flyway`, now at version v1 (execution time 00:00.167s)
契约断言通过：班级与课程保持解耦。
```

注意最后一行：断言是在 **Flyway 建出来的库**上跑的，不是 mysql 客户端建的库。
这才是 Gate 想要的顺序——迁移先用起来，再验结构。

### 为什么不在本机跑（记录备查）

三条路都试过，全部卡在环境而非代码：

| 尝试 | 现象 |
|---|---|
| `docker run flyway/flyway:9 migrate` | 进程被 SIGKILL（exit 137）；`docker run --rm mysql:8.0 echo hi` 同样被杀，而 `docker exec` 正常 |
| `docker create` + `docker start` | create 成功（拿到容器 ID），start 被 SIGKILL，容器停在 `Created` |
| brew 装 flyway CLI | `brew install flyway` 因 `/opt/homebrew/var/homebrew/locks` 权限被拒；GitHub Release 的 379MB 包下载 300 秒只到 15MB（≈50KB/s）；Maven Central 直连超时 |

用 `mysql` 客户端直接应用 DDL 的等效验证也做过（15 张表齐全），但它不覆盖 Flyway 的版本表与校验和，
所以最终没有拿它当 Gate 证据，而是把 CI 打通。**这条经验对 B6 有用**：本机 `docker run/start` 不可用，
WP-12 的 compose 联调同样会受影响，需要提前想替代方案。

## 给下一个包的话

1. **契约已冻结**（`contract-v1`）。任何字段变更先提 CR，`contracts/` 不接受"顺手改一下"。
2. **`rejectGate` 是小写**，`liveness`/`identity`/`action_count`/`multi_face`/`no_face`/`match`。
   它和其他枚举的大写约定相反，这是文档 §13.2 的原样要求，不是笔误。Java 侧建议用
   `@JsonValue` 显式映射，别靠 `Enum.name().toLowerCase()` 碰运气。
3. **两个生成列不许读写**：`account.admin_singleton`、`appeal.pending_attendance_id`。
   MyBatis-Plus 实体里请标 `@TableField(exist = false)` 或直接从实体里去掉，
   否则 insert 会报 "The value specified for generated column is not allowed"。
4. **B2 的方向依赖**：`fa-org` 只依赖 `fa-common`，不要反向让 `fa-common` 依赖 `fa-org`。
   `DataScope` 注解放 `fa-common`，切面实现放各模块自己的 `config/`。
5. **课程 DTO 的 `additionalProperties: false` 不是摆设**：B2 的 `@RequestBody` 要用
   `FAIL_ON_UNKNOWN_PROPERTIES`（Spring Boot 默认 `false`，需要显式打开），
   否则场景 16「带 classId 创建课程」不会被拒。这条已在 §16.3 列为验收项。
6. `db/seed/seed.sql` 里那 33 条 `sys_config` 是**阈值的第一份真实来源**。
   B3 的 `calibrate.py` 标定后应 `UPDATE` 这些行（`editable=0` 的三条由脚本写），
   不要在代码里另留一套默认值。
