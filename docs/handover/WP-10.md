## 3. 三个刻意的实现决定

### 3.1 错误只认 `code`，不解析 `message`

`client.ts` 的 `request()` 里 `code !== 'FA-0000'` 即失败，
文案优先用后端 `payload.message`（更具体，如「仍有 3 名在读学生」），
回落到本地 `ERROR_MESSAGES`。这样后端改文案不会打破前端判断，
而 `errors.ts` 是从 `contracts/enums/error-codes.json` 逐条抄的 33 条，不手写。

### 3.2 唯一性预检放在失焦，不放在提交

班级码/课程编码的重复检查在 `@blur` 时打一次 `keyword` 精确匹配的列表请求。
提交才报错的表单，在连续录入 20 个班时会被打断 20 次。

### 3.3 大屏不出现滚动条（§14.3 验收项）

`SessionLiveView` 整页 `position: fixed; overflow: hidden`，
字号全部用 `clamp(...vw, ...vh)` 跟视口走，名单区 `flex-wrap` + `overflow: hidden`，
放不下就用「还有 N 人未到」收口。1920×1080 与 1366×768 均无滚动条。


`element-plus` 全量引入 306KB gzip，对管理端可接受（§7.4.1 的 200KB 预算只约束移动端），
已单独切 chunk 以便长期命缓存。若将来要做按需引入，改 `manualChunks` 为
`unplugin-vue-components` + `ElementPlusResolver` 即可，页面代码不用动。

## 5. 与契约对齐时改掉的两处

| 位置 | 原写法 | 改为 | 原因 |
|---|---|---|---|
| 学生状态枚举 | `ACTIVE/TRANSFERRED/INACTIVE` | `ACTIVE/TRANSFERRED/**ARCHIVED**` | 契约与 DDL 都是 `ARCHIVED` |
| CSV 导入 | 手写 `fetch` + 数字 code 判断 | 复用 `request()`（认得 FormData） | `Result.code` 是 `FA-0000` 字符串，手写会永远判失败 |
