## 关键实现决定

### 1. 删除班级的三种结局（顺序不能反）

```
有 ACTIVE 学生 → FA-2005（带 studentCount），什么都不改
被会话引用     → status=ARCHIVED，返回 archived=true
都没有         → 物理删除，返回 archived=false
```

顺序反了会出现「用户看到不能删，但状态已经变了」。

### 2. CSV 导入没有 `@Transactional`

§14.3 要求「已成功的行不回滚」。整批一个事务的话，1000 行里错 1 行就全废，
教师面对 1000 行数据会陷入「改一个错、再传一次、永远传不完」的循环。
现在是逐行校验 + 每 100 条刷一次，成功就是成功。

### 3. 数据范围的两个反直觉点

- **空集合 = 无权限**，不是「不过滤」。`if (allowed != null && allowed.isEmpty()) return empty;`
  这一行少了就静默越权。
- **越权访问用 FA-2006（403），不用 404**。404 会让前端无法区分「不存在」和「不归你」，
  而教师需要知道是「这个班不归我」，好去找管理员授权。

### 4. 课程 DTO 的防线是两层

- 契约层：`CourseCreateReq` 没有 `classId`，OpenAPI `additionalProperties: false`；
- 运行时：`spring.jackson.deserialization.fail-on-unknown-properties: true`，多传字段直接 400。

只靠其中一层都不够：契约能让前端 codegen 报错，但挡不住 curl；运行时能挡 curl，
但如果没有契约约束，将来有人「顺手」加字段就不会被发现。

## 给下一个包的话

1. **不要给 `Course` 加任何班级字段**。评审时先看 `CourseDtos` 和 `Course.java` 有没有多出 `classId`，
   这是 D7 最容易破防的地方。
2. **`teacher_scope` 是授权表不是关联表**。B4 查会话/考勤时用它做边界，
   不要试图从它推导出「课程属于哪些班」——那是另一种关系，v2.0 不存在。
3. **`@DataScope` 只在 Service 生效**。B4 新增的 `SessionService` / `AttendanceService`
   必须加在方法上，否则教师能看到全场数据。
4. 会话创建要**同时**校验班级与课程授权（`ScopeContext.requireClassAndCourse`），
   缺一即 `FA-2006`——这是 §3.1 的硬要求，也是最容易只判一个的地方。
