# 主动活体（动作挑战）真实-world APCER/BPCER 评测协议

状态：**已发布，待真机执行** · 建立日期：2026-11-23
评测脚本：`face-service-python/scripts/eval_active_liveness.py`

## 1. 背景：为什么合成验证不闭环

被动活体的三轮合成标定已证明零区分度（`passive.py` / `calibrate_passive.py` 标定状态）：
bicubic 重采样链复现不了屏幕摩尔纹的真实物理。该结论对**主动活体动作判据**同样成立——
但缺口的位置不同：

| 验证层次 | 合成实验能证明 | 合成实验测不出 |
|---|---|---|
| 判据保真度（probe_action --scale/--eye/--pose） | 信号-噪声分离度 ≥3σ、计数器分段逻辑 | 真人动作幅度分布 → BPCER |
| 攻击可达性（本协议） | MOVE_*/TURN_* 的**几何信号通道**是否可达（见 §2 同构论证） | 翻拍质量对 SCRFD 检出的影响、预录视频与屏幕重放的真实呈现 |

`probe_attack.py` 只覆盖了活体模型（minifasnet）对静态照片的拒绝率；
动作门禁对攻击的放行率（APCER）从未被测量过。本文档把它变成可执行、可复跑的规程。

## 2. 攻击通道分析（缺口在哪、为什么）

主动活体的判据全部是**几何/亮度统计**：bbox 尺度（MOVE_*）、5 点偏航投影（TURN_*）、
眼框暗度（EYE_CLOSE）。据此把真实攻击按物理通道分四类：

| 通道 | 攻击形态 | 覆盖动作 | 判据层面可否区分 | 原因 |
|---|---|---|---|---|
| A. 几何平移 | 打印照片/手机屏幕**物理靠近或远离**摄像头 | MOVE_CLOSER / MOVE_AWAY | **不能**（原理性缺口） | 照片靠近时 bbox 尺度变化与真人靠近**完全同构**——几何判据不读纹理 |
| B. 3D 倾斜 | 照片/屏幕**3D 倾转**（左右偏转） | TURN_LEFT / TURN_RIGHT | **不能**（原理性缺口） | 照片是刚体，倾斜时的 5 点投影与真人转头同构。CASIA 平面贴图的投影变换造不出此信号，故合成实验一直测不出这条通道 |
| B'. 平面滚转 | 照片/屏幕**原地旋转**（歪头拿） | TURN_* | 部分 | yaw_proxy 沿眼轴投影消滚转，但残余漂移实测 max≈0.108，距 turn_delta=0.12 仅 1σ（CR-021 已知限制） |
| C. 无信号 | 静态照片静置 | EYE_CLOSE / 全部 | 可区分 | 无变化源，计数恒 0 |
| D. 重放 | **预录视频**（本人或他人做动作的录像）对屏播放 | 全部 5 个 | 不能（原理性缺口） | 视频里动作信号完整。残余防线=活体模型门禁+被动活体门禁（默认关）+随机抽签 |

**结论**：MOVE_*/TURN_* 存在几何同构攻击通道。调阈值（delta）无法闭合它——
同构意味着「能放行真人动作的 delta 必然放行照片移动」，唯一的杠杆是压 BPCER 的阈值
反向抬升 APCER 不变。缺口闭合只能靠分层防御（活体模型门禁、被动门禁、CR-025 遮挡门禁），
因此本评测的目标不是「调阈值」，而是**量化每个通道的残余风险并给出分层防御的开启依据**。

## 3. 指标定义（ISO/IEC 30107-3 映射）

- **一次呈现（presentation）** = 一次完整挑战：`start`（基线帧）→ `frame`×N（按 seq 顺序）
  → `finish`。与生产完全同链路（同一 detector/landmarker/计数器/门禁）。
- **APCER**（攻击呈现分类错误率）= 被判「通过」的攻击呈现 / 攻击呈现总数。
- **BPCER**（真人呈现分类错误率）= 被判「失败」的真人呈现 / 真人呈现总数。
- **双层口径**（报告必须分列，不能混）：
  - **组件级**：只看 `actionCount` 门禁——回答「动作判据本身放不放行」。
    这是本协议的主指标；liveness/identity/match 门禁的明细照记但只作旁证。
  - **系统级**：全部门禁 AND 的最终 `passed`——回答「这条攻击在系统里能不能签到成功」。
    要求向量库里预注册攻击目标身份（1:N match 才有判可言）。

## 4. 素材矩阵（真机采集）

攻击侧（每格 = 独立挑战场数）：

| 攻击类型 | MOVE_CLOSER | MOVE_AWAY | EYE_CLOSE | TURN_LEFT | TURN_RIGHT |
|---|---|---|---|---|---|
| print-static（A4 打印静置） | ≥5 | ≥5 | ≥5 | ≥5 | ≥5 |
| print-move（照片物理靠近/远离） | ≥10 | ≥10 | ≥5 | ≥5 | ≥5 |
| screen-move（手机屏显示照片移动） | ≥10 | ≥10 | ≥5 | ≥5 | ≥5 |
| screen-tilt（屏幕 3D 倾转） | - | - | ≥5 | ≥10 | ≥10 |
| replay-video（预录动作视频播放） | ≥5 | ≥5 | ≥5 | ≥5 | ≥5 |

真人侧（BPCER）：**≥10 人 × 5 动作 × 每动作 ≥10 场**（与 §4.4.4 误拒可归因验收线一致）。
每次采集 = 基线静置约 2 秒 + 按提示完成动作；教师手机后置摄像头，教室光照，320×240 帧率约 3fps（与服务端消化率一致）。

## 5. 数据落盘格式（`--real` 模式输入）

```
<root>/
├─ attacks/<attack-type>/<ACTION>/<case-id>/baseline.jpg
│                                          seq_000.jpg ...（按采集顺序编号）
└─ bonafide/<ACTION>/<case-id>/baseline.jpg
                                             seq_000.jpg ...
```

- 每场挑战一个目录；`baseline.jpg` 是 start 的基线帧，`seq_*.jpg` 是按上传顺序的帧。
- 目录名即元数据，不允许出现矩阵之外的 attack-type / ACTION 拼写。
- 报告由脚本自动生成（md + json），人工不做统计。

## 6. 判定与统计规则

- 帧不足 `min_frames=8` 或触发 FA-4001/4002/4009 中止的呈现，计入该动作的失败
  （BPCER 口径），攻击侧计入被拒（APCER 分母保留，防止「攻击做一半就收」的假阴性）。
- `rejectGate=match` 的攻击呈现：组件级照常统计 actionCount，系统级判拒。
  **攻击者冒充的目标身份必须预先入向量库**（评测脚本用基线帧特征注册），
  否则系统级数据无效。
- 真人侧 `rejectGate=actionCount` 的呈现要逐场留存门禁明细（value/threshold），
  用于误拒归因——这是验收线 ≤5% 的复核材料。

## 7. 验收线与决策映射

| 结果 | 动作 |
|---|---|
| BPCER（组件级）≤5%，各动作均达标 | 动作判据闭环，验收通过 |
| 某动作 BPCER >5% | 归因该动作的 value/threshold 分布，评估 hold/delta 是否回调（回调须重跑全量 pytest + e2e） |
| MOVE_*/TURN_* 组件级 APCER 显著 >0（预期成立） | 不调阈值；依据数据决定：a) 开启 PASSIVE_GATE（须先完成被动真机重标）；b) 前端在 MOVE_* 提示语中加「请眨一下眼」类并发动作的可行性评估（新 CR） |
| replay-video 组件级 APCER 高（预期成立） | 量化后作为「被动活体门禁必须开启」的验收依据；在此之前维持 PASSIVE_GATE=0 + 活体模型门禁兜底 |

## 8. 当前状态与代理评测的边界

`eval_active_liveness.py --proxy` 可在本机先行运行：用几何同构素材（同图缩放=照片平移、
CASIA 真实姿态对=照片倾转）驱动完整挑战链，输出**信号通道可达性**的量化预测。
边界（报告内固定声明）：

1. 代理素材不过翻拍通道（无打印/屏幕物理），检出质量按干净帧计 → 组件级 APCER 是
   **上限估计**（真实翻拍只会让检出更差、放行更少）；
2. EYE_CLOSE 无代理（无信号通道，静态负例覆盖）；replay-video 无代理（真机采集）；
3. BPCER 不可代理——真人数据必须走 `--real`。
