# CR-026 · 课程授权学生（班级名单之外的课程级签到授权）

- 提出人：主人（2026-11-23 会话内指示「课程管理端应该增加授权学生功能，选择班级、学生后可将该课程归给该学生实现签到功能」）
- 提出日期：2026-11-23
- 状态：✅ **已批准并实现**
- 关联：D7（受控扩展）/ §5.3.1 / §14.3 应到名单 / CR-001（快照冻结）/ contracts FA-2008
- 影响工作包：WP-01（组织主数据）、WP-04（会话快照）、契约三处、管理端

## 1. 动机

D7 把「应到名单 = 班级全体在读学生」简化掉了一切选课关系，换来零维护成本。
但两类真实场景被这个简化挡在门外：

1. **跨班上课**：学生 A 在计科 1 班，选修了本应给计科 2 班上的课——
   教师对该班发起签到，A 看不到、也签不了。
2. **转班补授**：学生转班后原课程还要继续上（毕业班补课、重修跟读），
   转走那一刻起该生就再也进不了原课程的签到。

本 CR 给课程增加一个**课程级的学生授权名单**：课程管理端选班级、选学生，
把该课程单独授权给指定学生；发起签到时，授权名单并入应到快照。

## 2. 与 D7 的关系（受控扩展，不是推翻）

- D7 的主体不动：`course` 表**依然没有** classId / grade；班级与课程依然
  互不引用；「班级 × 课程」依然是发起签到的唯一组合。
- `course_student` 选课表**依然不建**。新表 `course_student_grant` 是
  **授权表**（与 `teacher_scope` 同类，授权口径是"点名补充"，不是选课关系）：
  - 班级名单是**默认应到**，授权学生是**追加**（并集），二者语义不同；
  - 一门课通常只授权个位数学生，不存在「40 人 × 10 门课 = 400 条关系」
    的维护成本（D7 当年否掉选课表的核心理由）；
  - 会话点名依然以 `session_expected` 快照为准，授权变动不影响已存续会话。

## 3. 方案

### 3.1 数据模型（V9）

```sql
CREATE TABLE `course_student_grant` (
  id BIGINT AUTO_INCREMENT PK,
  course_id  BIGINT NOT NULL,
  student_id BIGINT NOT NULL,
  granted_by BIGINT NULL COMMENT '操作人（account.id），审计冗余',
  created_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_csg_course_student (course_id, student_id),
  KEY idx_csg_student (student_id)
)
```

- 不建物理外键（已拍板项）；
- 撤销授权 = 物理删除行（与 `teacher_scope` 同风格，审计里有痕迹）；
- 无 status 列：授权名单只在「会话创建那一刻」被读，软删没有业务语义。

### 3.2 应到快照并入（§14.3 公式更新）

```
session_expected = (班级 ACTIVE 学生) ∪ (该课程授权学生 ∩ ACTIVE 学生)
```

- 快照时机不变：仍由 `SessionService.create` 在会话创建时一次性写入；
- 已存续会话**不追溯**：授权/撤销只影响之后新发起的会话（CR-001 同理由：
  历史名单动了等于篡改考勤）；
- `session_expected.class_id` 对授权学生取其**当前班级**（列注释已写明
  「快照时的班级，便于排查转班」）。

### 3.3 授权端点（挂课程资源下）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/courses/{courseId}/grants` | 授权名单（分页，含学生姓名/学号/班级） |
| POST | `/api/v1/admin/courses/{courseId}/grants` | 授权 `{studentId}`；重复 → **FA-2008** |
| DELETE | `/api/v1/admin/courses/{courseId}/grants/{studentId}` | 撤销授权 |

权限沿用课程管理端：`TEACHER` + `ADMIN`；`@DataScope` 校验
`requireCourse(courseId)`。教师授权/撤销时，**目标学生的当前班级必须也在
该教师的班级授权范围内**（授权学生本质是动别人班的学生，不能越过班级
可见性；管理员不受限）。学生不存在或不在读 → FA-2001（文案覆盖）。

级联清理：课程物理删除、学生物理删除时删除对应 grant 行（两个模块都有
物理删除分支）。

### 3.4 前端（管理端课程页）

课程操作列加「授权学生」→ 抽屉：上区「选班级 → 选学生 → 授权」
（班级下拉来自授权范围，学生下拉随班级联动）；下区已授权学生表
（姓名/学号/班级/授权时间/移除）。教师只见自己授权范围内的班级与课程。

## 4. 不做的事

- **不做批量选课 / 整班授权**：整班直接用班级点名，授权表只收散生；
- **不做「按授权名单完全替代班级点名」**：语义混进选课表就是 D7 否掉的东西；
- **不追溯已存续会话**；
- **不动 Agent 与移动端**：学生端「可签会话」以 `session_expected` 为判据，
  授权学生并入快照后自然可见、可签（MobileCheckinController 注释里的
  「插班生」场景即为此设计）。

## 5. 契约影响

- 新错误码 **FA-2008 · 409 · 该学生已被授权此课程**（组织段顺延，2008/2009 空缺）；
- `java-api.yaml` 新增 `CourseGrant*` 三个端点与 `CourseGrantResp` schema；
- `ErrorCodeContractTest` 36 → 37；两份 `errors.ts` 同步。

## 6. 验收口径

1. 授权学生后，教师对**授权学生所在班以外**的班级 × 该课程发起签到，
   授权学生移动端能看到该会话并正常刷脸签到；
2. 撤销授权只影响新会话，历史会话考勤不变；
3. 教师试图授权「授权班级范围外」的学生 → FA-2006；
4. 重复授权 → FA-2008；学生不存在/已归档 → FA-2001；
5. 课程删除（无会话引用路径）与学生删除后，孤儿授权行不残留。
