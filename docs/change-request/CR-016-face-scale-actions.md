# CR-016 · 动作库新增「靠近 / 离远」

- 提出人：主人（2026-11-21 会话内指示「动作库动作增加：靠近、离远」）
- 提出日期：2026-11-21
- 状态：✅ **已批准并实现**
- 关联：§4.4.1 动作库 / §4.4.3 挑战规则 / §4.4.4 连续段判定 / §10.5 配置项
- 影响工作包：WP-06（Python 活体与动作）、WP-11（移动端指令渲染）、WP-13（E2E）

## 1. 动机

v2.0 的白名单只有张嘴一族（`MOUTH_ONCE` / `MOUTH_TWICE`），随机性全部压在「做几次」上：
**指令种类只有一类**。对手只要拍到一段张嘴视频，就能覆盖全部挑战；学生端也容易靠
「一直保持张嘴」蒙过去。

新增「靠近 / 离远」两个动作，让指令在**空间维度**上也能变化，且判据不需要新的模型、
不增加客户端负担。选这两个动作的理由很直接：它们改变的是人脸在画面里的**尺寸**，
而尺寸是检测器每帧都在算的量。

## 2. 方案

### 2.1 判据

| 项 | 约定 |
|---|---|
| 指标 | `scale = sqrt(检测框宽 × 高) / 画面宽`（线性尺度，分辨率归一） |
| 基线 | `challenge/start` 的 `baselineFrame`（与嘴部动作同一套"指令前中性帧"） |
| 通过条件 | `scale / baseline >= 1.18`（靠近）或 `<= 0.82`（离远），且**连续 ≥2 帧** |
| 次数 | 1 次（`need = 1`）——「连续靠近两次」没有物理意义 |
| 窗口 | 2.5 秒 / 10 帧（挪动 + 保持半秒，比张嘴需要更长窗口） |
| 落点 | `app/challenge/action.py: ScaleActionCounter`；`gates.gate_action` 按动作分派 |

### 2.2 三个设计决定

**① 用检测框尺度，不用关键点。** §4.4.1 的全局约束是「关键点只用于定位 ROI，判动作用
ROI 亮度统计」，原因是 `2d106det` 是形状回归器，会把偏转与形变归一化掉。bbox 尺度不
受这条限制：它是 SCRFD 在**原图像素坐标**下给出的量，人脸靠近镜头就变大，正好是
「距离变化」的直接测量。因此本次把约束扩写为「亮度统计**或**检测框尺度」，两者都
不经过形状归一化。

**② 用几何平均，不用宽度。** 侧脸 30° 会让 bbox 宽度缩掉约 13%，高度基本不变；
`sqrt(宽×高)` 只缩约 7%。用宽度的话，「转了下头」离 18% 阈值只剩 5 个点，迟早被误判
成「离远」。

**③ 方向必须相对基线判，不能用「序列最大 / 最小之比」。** 用极差的话，学生前后晃一下
就同时满足「靠近」和「离远」——两条指令退化成「随便动一下」，随机性归零。另外，
**没检出人脸的帧记「动作不成立」而不是 0**：记 0 时 `MOVE_AWAY` 会把它白捡成做对了
（`0 < base × 0.82` 恒成立），画面糊掉反而更容易过。

### 2.3 可做性门槛（不让学生做做不到的动作）

抽样在 `start` 时进行，**先算完基线再抽动作**（顺序改了，见 §4 影响面），并剔除当前
画面上做不到的动作：

| 动作 | 门槛 | 不满足会怎样 |
|---|---|---|
| `MOVE_CLOSER` | 人脸长边 × 1.18 ≤ 画面高 × 0.80 | 框被画面边缘截断后尺度不再增长，学生越靠越近、比值却卡住 → 判失败 |
| `MOVE_AWAY` | 人脸短边 × 0.82 ≥ 70px | 缩完掉出检测下限（`subject_min_px = 60`），连续无脸 → `FA-4001` 中止 |
| 两者 | 基线帧必须检出人脸 | 判据是「相对基线的变化」，没有基线无从判起 |

剔除只针对单个动作，不合格的那个退出抽签，其余照旧；若全部不合格则退回嘴部动作
（它们不依赖尺度）。客户端 hint 路径（`FA_ALLOW_ACTION_HINT=1`）不受门槛约束，
否则联调无法构造「做不到」的负例。

### 2.4 为什么把 `subject_min_px` 单独放宽到 60

`multi_face_min_px = 90` 同时承担两个职责：数「画面里有几张脸」和判「有没有脸」。
`MOVE_AWAY` 会主动把人脸缩小，若仍按 90px 判无脸，**学生照做反而被判 `FA-4001`**。
所以尺度类动作的「主体脸」下限单独放宽到 60px；多脸计数仍用 90px，免得背景里的
小脸把一次正常签到打断。

## 3. 阈值依据（`probe_action.py --scale` 实测）

同一张 CASIA 人脸按不同倍率重贴（1280×720 画布，基准人脸 320px），逐帧跑真实检测器：

| 序列 | 期望次数 | 检出 | 实测倍率 |
|---|---|---|---|
| 静止 | 0 | 0 | 1.00 |
| `MOVE_AWAY@0.82` | 1 | 1 | 0.82 |
| `MOVE_AWAY@0.90` | 0 | 0 | 0.90 |
| `MOVE_CLOSER@1.10` | 0 | 0 | 1.13 |
| `MOVE_CLOSER@1.18` | 1 | 1 | 1.21 |
| `MOVE_CLOSER@1.30` | 1 | 1 | 1.36 |

- **10% 的挪动判 0**：阈值不是「动了就算」，小幅晃动不能刷过。
- **方向判据互不代偿**：6 个序列里反向判据全部为 0。
- **静止波动**：抖动 ±4px + JPEG q60 + 亮度 ±5%（12 帧）→ `std = 0.0131`。
- **分离度**：`delta = 0.18` / `std = 0.0131` = **13.7σ**（§4.4.1 门槛 3σ）。

实测倍率比名义倍率略大（1.18 → 1.21），因为检测框在更大尺度下会多框进一点头部；
方向上不影响判定，实际效果是「学生做的幅度略小于 18% 也可能通过」。

## 6. 已知限制

1. **真人未标定**。以上是合成素材的指标保真度结论。真人「举着手机边看屏幕边挪动」的
   姿态、运动模糊、自动曝光收敛都未实测。上线后需按 §13 的验收方式录 10 组真人视频
   复核准确率，与张嘴动作的真人标定一并作为遗留项。
2. **`MOVE_AWAY` 会降低末帧质量**。`match` 门禁用的是 `last_emb`，人脸缩到 0.82 倍后
   特征质量略有下降（112×112 对齐后差异不大，但远距离 + 弱光会叠加）。若线上出现
   「动作过了但 match 掉了」，优先怀疑这一条。
3. **俯仰会缩高度**。低头看屏幕时 bbox 高度会变小，几何平均约吃一半影响。当前 18%
   阈值下不至于误判，但阈值不能往下调（调到 12% 以下就有风险）。
4. **窗口内只判一次**。`need = 1`，学生做完不必回位；末帧可能仍处于「贴近」或「远离」
   姿态，这是设计选择而非缺陷。

## 7. 回滚

`FA_ACTION_WHITELIST=MOUTH_ONCE,MOUTH_TWICE` 后重启容器即可把新动作摘出抽签，
不需要重建镜像、不需要回退代码；已产生的 `attendance.action_seq` 仍可正常读取。
