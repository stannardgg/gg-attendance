# mobile-web — 学生签到端

学生扫码进入、做人脸 + 指定动作、看到本人结果。**只处理本人数据。**

## 页面

| 页面 | 说明 |
|---|---|
| 登录 / 激活 | 学号 + 密码；激活用「学号 + 姓名 + 班级码」 |
| 首页 | 进行中的签到卡片（含班级名与课程名） |
| 扫码入口 | `/checkin?sid&tk`，校验二维码、展示剩余时间；班级不符直接提示 |
| 采集页 | **先静默抓基线帧 → 同帧显示指令并开始采集**；多脸（≥90px）遮罩阻断 |
| 结果页 | 成功 / 失败原因 / 重试 / 申诉（失败 3 次后只剩申诉） |
| 人脸采集 | 5~10 张多状态样本，质量不达标不允许提交 |
| 我的 | 人脸状态、签到历史 |

## 三条容易做错的地方

1. **基线帧必须在指令出现之前抓**，且指令渲染与首帧采集同一帧触发，中间不能插等待动画。
2. **采集节奏由本地定时器保证（250ms/帧），上传串行但可积压最多 4 帧**。不能"上一帧不返回就不采下一帧"，否则实际帧率被 RTT 拖到 2~3 fps，`MIN_FRAMES=8` 永远达不到。
3. **设备枚举必须在开流之前**，开流后不要再 `enumerateDevices()` —— 部分 Windows 驱动会把正在用的流掐掉。

## 边界

- 不展示任何其他学生的信息（名单、统计一律不请求）。
- 不缓存人脸帧到本地存储。

## 技术栈
前端渲染
Vue 3 + Vite + TypeScript + Vant 4。`getUserMedia` 强制 HTTPS（开发期用 mkcert）。
